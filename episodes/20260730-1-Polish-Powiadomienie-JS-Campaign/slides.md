## Identifying the Victim — Source IP

```
$ duckdb -c "LOAD zeek; LOAD inet;
  SELECT DISTINCT id_orig_h
  FROM read_zeek('output/conn.log')
  WHERE split_part(id_orig_h::STRING, ':', 1) NOT IN ('fe80', '');"
┌──────────────────┐
│    id_orig_h     │
│      inet        │
├──────────────────┤
│ 192.168.100.12   │
└──────────────────┘
```

`split_part(...)` splits by `:` — this filters out IPv6 `fe80::` and `::` addresses, leaving only the real IPv4 host.

<!--
- From conn.log: only one unique IPv4 source address. The rest are IPv6 link-local and unspecified.
  - split_part(id_orig_h::STRING, ':', 1) takes the first segment before the colon.

## Detection — Zeek Script: HTTP Rule

```bash
const ip_api_uri_re = /\/line\/\?fields=hosting/;

# http_all_headers fires after all headers are received,
# so c$http$host is already set
event http_all_headers(c: connection, is_orig: bool,
                       hlist: mime_header_list)
{
  if ( ! is_orig ) return;
  if ( c$http?$host && c$http$host == "ip-api.com" &&
       c$http?$uri && ip_api_uri_re in c$http$uri )
    NOTICE([$note=HTTP_IpApi_HostingCheck,
            $msg=fmt("Host %s made anti-sandbox request: GET %s",
                     c$id$orig_h, c$http$uri),
            $conn=c]);
}
```

Checks both the URI path AND the `Host: ip-api.com` header.

<!--
- This rule catches the anti-sandbox ip-api.com HTTP request. The specific URI `/line/?fields=hosting` is unique to malware — typically, legitimate software does not query ip-api.com to ask "am I in a data center?"
  - JOKE: The malware asked "am I in a sandbox?" before stealing passwords. That's more situational awareness than most interns.

## Detection — Zeek Script (cont.) — C2 & Exfil

```bash
const exfil_file_re = /^PW_.+\.html$/;

                  query: string, qtype: count, qclass: count)
```

## Blue Team Takeaway #3

### JavaScript Attachments Are Executables

`.JS` files are not "documents." They run code. Treat them like `.EXE`.

> Windows Script Host (wscript.exe / cscript.exe) launching from email attachments is the canary.

<!--
- Takeaway three: .JS files are executables, not documents.
  - Windows Script Host (WSH) is the Windows component that runs .JS files. Double-clicking a .JS file launches wscript.exe which executes it — no different from running an .exe.
  - WSH provides the ActiveX objects this malware uses: WScript.Shell, Scripting.FileSystemObject, etc.
  - JOKE: Users think it's a document. Windows treats it as an executable. The attacker thanks you for your confusion.
- Policy recommendations:
  - Block JS attachments at the email gateway.
  - If users need JS files, use a controlled process (zip with password, developer channel).
  - Monitor wscript.exe and cscript.exe spawning from Office/email.
-->
